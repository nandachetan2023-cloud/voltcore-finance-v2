# Finance Help Chatbot — Implementation Plan

A **self-contained, offline knowledge-base chatbot** scoped to the **finance module only**. No AI/API keys needed — answers come from curated finance documentation bundled in the app. It covers (a) how to use finance features, (b) finance concepts/workflows, and (c) click-to-navigate quick-links.

## Scope & Behavior
- The chat widget renders **only when a finance sub-module is active** (checks `activeModule` against the finance tree in `erp-store.ts`). Hidden on HRMS, sales, etc.
- Floating button (FAB) bottom-right → opens a right-side `Sheet` panel with a chat UI.
- Local KB search: keyword + section matching over a curated `help-data` map. Renders Markdown-style answers (bold, lists, code) using the existing `react-markdown` dependency.
- Each answer can include **quick-link chips** that call `setActiveModule(...)` to jump the user to the relevant module (e.g. an answer about invoices has a "Go to Site Invoices" button).
- Conversation UI: user bubbles + assistant bubbles, suggested starting questions, persisted in component state per session.

## Files to Create

### 1. `src/components/help/finance-help-data.ts` (the knowledge base)
A typed data module — array of KB entries, each:
```ts
{ id, title, keywords[], summary, body (markdown), relatedModule?: ModuleId, links?: {label, moduleId}[] }
```
Curated content covering (scoped to finance only):
- **Running the app**: `npm install` → `.env` (`DATABASE_URL`, `SUPERADMIN_DATABASE_URL`) → `npm run db:push` → `npm run dev` (port 3000); build/start commands; troubleshooting (chunk errors, DB connection).
- **Finance features (per module)**: Dashboard, Ledger, Accounts Receivable, Accounts Payable, Journal Entries (+ create flow), Bank & Cash, Taxation, Budget, Financial Reports, Sites, Parties, Site Invoices, Payment Center, Petty Cash, Payment Advices, Expense Claims, Site Expenses, Bank Reconciliation, Work Orders, Fixed Assets, P&L, Tally Sync, Sync Config.
- **Workflows/concepts**: Invoice→Payment→Ledger posting; GST tax invoice & printing; AP/AR lifecycle; Bank reconciliation; Petty cash reimbursement; Fixed asset depreciation; P&L roll-up; Tally sync flow.
- **Quick-links**: each entry maps to a `moduleId` so the chat can offer a "Open this module" chip.

### 2. `src/components/help/finance-help-chat.tsx` (the widget)
A `"use client"` component:
- Floating FAB button (`fixed bottom-5 right-5 z-50`, circular, accent `#f5a623`, `MessageCircle`/`LifeBuoy` lucide icon), visible only when a finance module is active.
- `Sheet side="right"` (`sm:max-w-md`) styled to match the dark theme (`bg-[#0a0c12]`/`border-[#252e3a]`).
- Chat body: `ScrollArea` with message bubbles; header with title "Finance Help" + clear-chat button.
- Input row: `Textarea` + Send `Button` (Enter to send).
- Matching logic: tokenize query → score KB entries by keyword/term/title overlap → return top match (or a "no match, here are popular topics" fallback with clickable suggestions).
- Renders answers with `react-markdown` (already a dependency).
- Uses Zustand `setActiveModule` for quick-link chips.
- Starting suggestions shown when conversation is empty.

### 3. Wire-up in `src/components/erp/erp-layout.tsx`
- Import `<FinanceHelpChat />`.
- Render it once inside the `ERPLayout` root `<div>` (after `<main>`, before closing tag ~line 610) so it persists across module switches.
- Visibility is handled inside the component (reads `activeModule` and only shows for finance module IDs) — so no logic changes to the layout itself.

## Styling & Conventions (matching the app)
- Dark theme tokens: `bg-[#0a0d12]`, `bg-[#161c24]`, `border-[#252e3a]`, accent `#f5a623`, text `#e2e8f0`/`#5a6878`.
- shadcn primitives: `Sheet`, `SheetContent`, `Button`, `ScrollArea`, `Textarea`, `cn()` from `@/lib/utils`.
- Icons from `lucide-react`.
- Markdown via `react-markdown` (already in deps).

## Non-Goals (per user direction)
- No AI / `z-ai-web-dev-sdk` integration, no `.z-ai-config`, no API route.
- No coverage of non-finance modules (HRMS, sales, procurement, etc.).
- No backend or DB changes.

## Verification
- `npm run lint` passes.
- `npm run dev` → log in, open any finance module → FAB appears; open non-finance module → FAB disappears.
- Type a question (e.g. "how to create a journal entry", "print gst invoice", "how to run the app") → correct KB answer renders; quick-link chip navigates to the right module.
- Empty/garbage query → friendly fallback with suggestions.

## Notes
- All finance sub-module IDs are already enumerated in `MODULE_TREE.finance` (`src/store/erp-store.ts:9`), so the "show only on finance" check is a simple `.includes()` against that list (or the finance-derived set) — no new constants needed.
- The KB data file is the single source to maintain; adding a new finance how-to is just a new entry in the array.
